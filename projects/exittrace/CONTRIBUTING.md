# Contributing

Thanks for helping improve ExitTrace.

## Development workflow

1. Create or claim a bead with `bd` before changing files.
2. Keep changes small and use conventional commits.
3. Add tests or fixtures for behavior changes.
4. Run the verification commands before opening a PR.

## Public-safety rules

Do not commit:

- real survivor-service audit reports without explicit permission,
- secrets, tokens, cookies, or credentials,
- private IPs, hostnames, local filesystem paths, or personal infrastructure details,
- screenshots or copied conversations containing personal data.

Use synthetic fixtures for demos and tests.
