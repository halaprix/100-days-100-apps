# Contributing

Thanks for considering a contribution to PipeTwin.

## Development rules

- Use conventional commits.
- Keep fixtures public, synthetic, or sanitized.
- Do not include secret values in logs, tests, issues, or examples.
- Open an issue or Bead-backed task before broad scope changes.

## Local workflow

1. Pick or create a Bead with `bd`.
2. Make the smallest useful change.
3. Add or update tests/fixtures when code exists.
4. Run the project checks.
5. Commit with a conventional commit message referencing the Bead.
